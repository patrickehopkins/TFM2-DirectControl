## Physical validation

Status: **PASS — physically validated 2026-09-20**.

The first attempted run still loaded the original v0.5.8 DLL because `install-dev.ps1` had rebuilt and reinstalled the old source checkout after the validation package was copied. The game log correctly rejected that DLL with the v0.6.0 PE fingerprint. Process-module inspection identified the loaded DLL by its original SHA-256, `cb405ccf127b3c0ff8b206f718cf6dce78bbc2b779514857bdab6e839d8bbc2b`.

After installing the guarded v0.6.0 validation DLL, process-module inspection reported SHA-256 `860ade4cb3200188206e0799c1e19d1b419a95da0a976b543787eba14bc5b131`. A complete match then passed without observed misbehavior:

- real-time simulation pacing;
- F-key selection;
- RMB movement and contextual attacks;
- MMB camera pan and mouse-wheel zoom;
- pause and resume;
- manual skills and return-home;
- Ctrl+End release to native full-speed completion.

This validates the relocated native targets, changed camera layout, and existing gameplay/control behavior on the supplied v0.6.0 executable.

## Source-build boundary

The validation DLL was produced from the last physically verified DLL by a guarded, byte-for-byte relocation of the build fingerprint, target RVAs, and changed camera offsets. The maintained implementation is the dual-build source profile in `src/simulation_probe.rs` and `src/camera_probe/base.rs`.

The remaining release check is to compile this branch normally with the shipped v0.6.0 stable SDK, install it through `scripts/install-dev.ps1`, and repeat a short startup/control smoke test. The installer now refreshes its ignored local SDK copy from the installed game before every build, preventing a stale ABI-8 SDK from surviving the migration. This check proves the source integration and ABI-9 rebuild independently of the validation DLL.
